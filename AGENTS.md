# Working on YEMENI HERITAGE

The repository is the permanent source of truth. At the start of every session, read this file, then `docs/MASTER_PLAN.md`, `docs/TASKS.md`, `docs/DECISIONS.md` and `docs/PROGRESS.md`. Inspect the checkout, identify the next approved incomplete task and continue there. Update the evidence and status after verification.

Keep the approved Copper & Coffee identity, architecture and phase boundaries. Follow `docs/CHANGE_CONTROL.md` before changing scope, architecture or visual identity. Use a dedicated branch and descriptive commits, open a pull request and leave merging to the owner.

Use semantic HTML, strict TypeScript and Server Components by default. Follow the design and motion system docs. Check both reading directions, keyboard behavior and reduced motion. Never present placeholder assets as approved cultural references.
